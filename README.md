# 수업 포트폴리오 웹앱

교사가 여러 수업을 만들고, 학생이 수업별로 직접 가입한 뒤 교사의 질문에 답변을 계속 누적하는 포트폴리오 앱입니다.

## 포함 기능

- 교사 회원가입 / 로그인
- 교사 1명이 여러 수업 생성
- 수업별 6자리 참여 코드 자동 발급
- 학생 수 제한 없음
- 학생 직접 등록: 수업 코드 + 이름 + 학번 + 비밀번호
- 기존 학생 로그인: 수업 코드 + 학번 + 비밀번호
- 교사 질문 수시 등록
- 학생 화면에서 5초 간격으로 새 질문 자동 반영
- 학생 답변 저장 및 수정, 누적 보관
- 교사 학생별 답변 현황 확인
- 전체 답변 `.xlsx` 다운로드
- 비밀번호는 bcrypt 해시로 저장
- 로그인 세션은 HttpOnly 서명 쿠키 사용

## 1. Supabase 준비

1. Supabase에서 새 프로젝트를 만듭니다.
2. SQL Editor에서 `supabase/schema.sql` 전체를 실행합니다.
3. Project Settings에서 다음 값을 확인합니다.
   - Project URL
   - service_role key

`service_role` 키는 브라우저에 노출하면 안 됩니다. 이 앱은 서버 코드에서만 사용합니다.

## 2. 환경 변수

`.env.example`을 복사해 `.env.local`을 만들고 값을 채웁니다.

```bash
cp .env.example .env.local
```

예시:

```env
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_SECRET_KEY=xxxx
SESSION_SECRET=아주-긴-무작위-문자열-32자-이상
```

## 3. 로컬 실행

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`으로 접속합니다.

## 4. 인터넷 링크로 배포

Vercel에 이 프로젝트를 배포하고, Vercel 프로젝트의 Environment Variables에 위 3개 값을 동일하게 등록하면 됩니다.

배포가 끝나면 하나의 링크만 공유하면 됩니다. 같은 프로그램 안에서 교사는 수업을 여러 개 만들 수 있으므로 수업별로 앱을 복제할 필요가 없습니다.

## 로그인 구조

### 교사
- 이메일 + 비밀번호
- 로그인 후 여러 수업 생성 가능

### 학생
- 처음 등록: 수업 코드 + 이름 + 학번 + 비밀번호
- 이후 로그인: 수업 코드 + 학번 + 비밀번호

같은 `2101` 학번이 여러 수업에 있을 수 있기 때문에 수업 코드를 함께 사용합니다.

## 데이터 구조

- `teachers`: 교사 계정
- `classes`: 수업
- `students`: 수업별 학생
- `questions`: 수업별 질문
- `answers`: 학생별 질문 답변

## 보안 메모

- 평문 비밀번호를 저장하지 않습니다.
- 데이터베이스는 service role 서버 접근만 허용하도록 RLS를 켜고 일반 클라이언트 권한을 제거했습니다.
- 학생은 서명된 서버 세션으로 자신의 질문과 답변만 접근합니다.
- 교사는 자신이 만든 수업만 조회할 수 있습니다.
